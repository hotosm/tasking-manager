## Investigación e Implementación de GitHub Projects (Kanban)

**Responsable:** *Alexandra Raquel Quispe Arratea* 

Investigar y definir el uso de GitHub Projects como herramienta central para la gestión colaborativa del proyecto, implementando un flujo de trabajo basado en Kanban integrado con Issues, labels, estados y mecanismos de seguimiento del avance del desarrollo.

### Descripción

La tarea consiste en analizar las capacidades actuales de GitHub Projects y establecer una configuración inicial alineada a las necesidades del proyecto. Se deberá investigar tanto las funcionalidades de planificación como las opciones de automatización disponibles dentro de GitHub para mejorar la organización, trazabilidad y control del ciclo de trabajo.

Asimismo, deberá implementarse un tablero Kanban funcional que permita gestionar tareas, prioridades y estados de avance de manera colaborativa.

### Responsabilidades

* Investigar las funcionalidades de GitHub Projects.
* Analizar diferencias entre Projects Classic y Projects (new).
* Diseñar un flujo Kanban adecuado para el proyecto.
* Definir columnas/estados del tablero.
* Configurar integración entre:
  * Issues
  * Labels
  * Milestones
  * Assignees
  * Estados automáticos
* Evaluar automatizaciones disponibles dentro de GitHub Projects.
* Proponer convenciones de uso para el equipo.
* Implementar una versión inicial funcional del tablero.

### Alcance mínimo

El análisis deberá contemplar como mínimo:

* Gestión visual del flujo de trabajo.
* Priorización de tareas.
* Automatización de estados.
* Integración con Issues y Pull Requests.
* Métricas o visualizaciones disponibles.
* Buenas prácticas de trabajo colaborativo.

### Entregables

* Tablero Kanban configurado en GitHub Projects.
* Configuración inicial de labels y estados.
* Documento técnico de investigación y conclusiones.
* Evidencia de integración entre Issues y el tablero.
* Recomendaciones de uso para el equipo.

### Criterios de aceptación

* Existe un tablero Kanban funcional y operativo.
* Los Issues pueden integrarse correctamente al flujo del tablero.
* Se documentaron las decisiones de diseño y configuración.
* El informe técnico explica ventajas, limitaciones y criterios adoptados.
* Se definió un flujo de trabajo entendible y reutilizable por el equipo.
