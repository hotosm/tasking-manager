# Estructura y Gobernanza del Equipo QA (qa-gestion)

Este repositorio centraliza las reglas, procesos, estándares y herramientas internas del equipo de Aseguramiento de Calidad (QA). Su objetivo es garantizar la consistencia en la forma de trabajar, facilitar el onboarding de nuevos integrantes y estandarizar la documentación organizacional.

Nadie debe documentar casos de prueba ni características del producto en este espacio.

## Estructura de Directorios

* `01-introduccion/`
  Orientada a la presentación del equipo humano. Contiene quiénes somos, la visión, objetivos, contexto del proyecto, roles, responsabilidades y guías de bienvenida (onboarding) para nuevos ingresos.
* `02-gestion-proyecto/`
  Almacena informes de gestión, tableros de control y lineamientos sobre el seguimiento de tareas (ej. uso y configuración de GitHub Projects).
* `03-automatizacion/`
  Documenta las estrategias, configuraciones y lineamientos para la Integración y Entrega Continua (CI/CD), como la implementación de GitHub Actions aplicadas a QA.
* `04-estandares/`
  Define las reglas inquebrantables del equipo. Incluye el **gobierno documental** (estructuras obligatorias de cada repositorio), convenciones de nomenclatura (por ejemplo, `nomenclatura-casos-de-prueba.md`), políticas de commits, flujos de ramas y guías de estilo.
* `05-reuniones/`
  Registro histórico de minutas, acuerdos, retrospectivas y estructura de las reuniones periódicas (Dailys, Plannings, Refinamientos).
* `06-plantillas/`
  Formatos base obligatorios para estandarizar el trabajo. Incluye plantillas Markdown para la creación de suites de prueba, reportes de ejecución, apertura de bugs (Issues) y Pull Requests. Todo nuevo documento debe nacer de una plantilla de esta carpeta.
